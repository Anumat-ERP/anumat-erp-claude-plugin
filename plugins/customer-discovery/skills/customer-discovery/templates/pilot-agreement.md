# Pilot agreement outline

An outline to agree terms in plain language before a pilot starts. Not legal
advice: have a lawyer review anything you sign. Why pilots need success
criteria: `${CLAUDE_PLUGIN_ROOT}/skills/customer-discovery/reference/experiments.md`.

**Parties:** [your company] and [customer]
**Pilot contacts:** champion ____, economic buyer ____, day-to-day users ____
**Dates:** start ____, end ____, review meeting ____

## 1. The problem
In the customer's words, what this pilot is meant to fix.

## 2. Success criteria (agreed now)

| Metric | Baseline today | Target by end date | How we measure it |
|---|---|---|---|
| | | | |
| | | | |

## 3. Scope
- Included: ____
- Not included: ____
- Number of users / sites: ____

## 4. What each side provides

| We provide | Customer provides |
|---|---|
| Software / service, setup, support hours | Access to data, a named owner, user time, feedback sessions |

## 5. Stage honesty
What is manual or unfinished today, stated plainly (for example "reports are
prepared by our team during the pilot").

## 6. Price
- Pilot fee: ____ (prefer paid, even discounted)
- Credited against the first paid contract: yes / no

## 7. On success
If the criteria in section 2 are met, the customer intends to move to a paid
contract of ____ at ____ per ____, starting ____.

## 8. On failure or early exit
How either side can end the pilot, and what happens to the customer's data.

## 9. Data and confidentiality
What data we access, where it is stored, who can see it, and when it is
deleted.

## 10. References
Whether the customer agrees to be a reference or case study if successful
(optional, and only with explicit consent).

**Signed:** ____ (customer)  ____ (us)  Date: ____
