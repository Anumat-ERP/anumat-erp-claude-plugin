# Preparation plan

A demo is a small project with a fixed deadline. It gets a plan, owners, and
a freeze date like any release. Produce the plan with
`${CLAUDE_PLUGIN_ROOT}/skills/demo-storytelling/templates/prep-plan.md`.

## First: the brief

Before planning, answer these. If you can't, ask the organisers.

| Question | Why it matters |
|---|---|
| What is the event, and who is in the room? | Judges, investors, customers and teammates want different things |
| What is the time limit, and is Q&A inside it? | Sets the script length |
| What decides success? A rubric, an investment, a signed pilot? | Sets the ask and what the script must prove |
| What equipment is provided? Screen, adapters, mic, Wi-Fi, clicker? | Sets the tech check |
| Is there a line check or rehearsal slot in the room? | The best rehearsal you'll get |
| Live demo, slides, or both? Are recordings allowed? | Sets the backup plan |
| Who is presenting, and in what roles? | Sets rehearsal and Q&A split |

## The countdown, T-7 to T-0

| Day | Goal | Key tasks | Output |
|---|---|---|---|
| **T-7** | Brief and story | Answer the brief; pick persona, job and framework; fill the story canvas | Story canvas agreed |
| **T-6** | Golden path | Choose the three ideas; cut features; list the exact path through the product; list what must be built or fixed for it | Golden path list, owners for fixes |
| **T-5** | First script | Write the run-of-show with times; table read; count words | Script v1, timed |
| **T-4** | Demo setup | Seed data, reset button, pre-filled forms, account set-up; first click-throughs | Reset works under 10 seconds |
| **T-3** | Full runs | Three recorded full runs; feedback; cut to 90% of time; draft Q&A top 10 | Script v2; Q&A draft |
| **T-2** | Backup and stress | Record backup video; disaster run; judging map (hackathon); cue cards | Backup on desktop, USB, cloud |
| **T-1** | Freeze and dress | **Code freeze on the golden path**; dress rehearsal on demo hardware; Q&A drill; pack the kit | Script frozen; kit packed |
| **T-0** | Deliver | Arrive early; tech check; line check if offered; warm-up; deliver; Q&A; note what happened | Delivered; retro notes |

T-0 timeline:

| Time before slot | Task |
|---|---|
| 2 hours | Arrive, find the room, find power and the stage connection |
| 60 to 30 minutes | Tech warm-up with the tech-check template; line check |
| 30 to 15 minutes | Final silent click-through; reset; close everything else |
| 15 to 0 minutes | Personal warm-up (breath, body, voice, mind) |
| 0 | Physiological sigh; walk on; first two lines |
| After | Retro notes within an hour, while memory is fresh |

## Compressed plan: hackathon (24 to 48 hours)

Map the same stages to hours before the final.

| Hours before final | Stage |
|---|---|
| Kick-off | Brief: read the rubric; pick persona and the one job |
| Midpoint | Golden path fixed; story canvas done; everything else is secondary |
| -8 h | Script v1; seed data and reset |
| -6 h | **Feature freeze**: only golden-path bugs from here |
| -4 h | Full runs, recorded; cut to time; judging map |
| -3 h | Backup video recorded and copied to USB and cloud |
| -2 h | Q&A drill; cue cards; disaster run |
| -1 h | Tech check; then the warm-up |

The most common hackathon failure is coding until the last minute and
rehearsing zero times. A working golden path rehearsed five times beats a
larger product rehearsed once.

## The kit list

- Laptop and charger; a second laptop with the demo ready if you have one
- HDMI and USB-C adapters, and spares
- Clicker with fresh batteries
- Phone charged, hotspot set up; power bank
- USB stick with the backup video and the slides
- Printed cue cards
- Water
