## Steps

**1. Read the product.** README, docs, the story canvas and script if they
exist, and the code for the parts judges will probe (the hard technical part,
data handling, anything AI).

**2. Brainstorm 20 to 30 questions** for this audience: the ten common ones
adapted to this product, plus the ones only this product invites. Rank by
likelihood and by damage if answered badly. Keep the top 10.

**3. Write each answer** in the three-part form. Evidence must be true and
sourced from the project; where a fact is missing, write `[NEED: …]` rather
than inventing a number.

**4. Assign an owner** per question from the team roles.

**5. The hard ones.** Pick the two or three questions the team would least
like to get. For each, name the fair point to agree with, then the answer.

**6. "Is this real?"** Write the exact sentence on what's live and what's
simulated.

**7. Bridge-back line.** One line that works for almost any question.

**8. Backup material.** Name the tab or slide for the two most likely
deep-dives.

## Output

The filled Q&A prep sheet. Offer to run a drill: you ask the questions one at
a time as a sceptical judge, the user answers, and you score each on length
and structure.
